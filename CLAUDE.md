### `scroll-behavior: smooth` использовать НЕЛЬЗЯ

Это была причина реального бага: владелец уходил вниз, возвращался наверх —
и первый экран пропадал, оставалась чёрная пустота с шапкой.

Браузерная плавная прокрутка отдаёт ScrollTrigger позицию скролла с задержкой,
триггеры первого экрана (их три, все на `scrub`) залипали в конечном состоянии,
где видео и текст выведены в `opacity: 0`. Плавность для якорных ссылок теперь
своя — `initSmoothLinks()` в `site.js` ставит позицию напрямую каждый кадр
через `requestAnimationFrame`, и ST видит её честно.

Триггерам первого экрана добавлен `invalidateOnRefresh: true`, а `refresh()`
дёргается после `loadedmetadata` ролика и после `window.load` — метаданные
видео и шрифты приезжают позже первого расчёта и сдвигают вёрстку.

**Расшифровки текста (scramble) на сайте нет.** Заголовки WORK / ABOUT / TOOLS
раньше «набирались» из случайных символов — владелец забраковал, снято
27.08.2026 вместе с самой функцией. Не возвращать.

**В финальной секции не должно быть зелёного свечения.** Первый вариант был с

3×3, девять работ, **все плитки одного размера и его не меняют**.

## Анимации

GSAP + ScrollTrigger. Владелец просил «ярко и эффектно», но всё держится на
таймингах, а не на количестве эффектов.

| Что | Где |
|---|---|
| Первый экран: видео из `scale 1.14`, строки заголовка выезжают из-под маски | `initAnimations()` |
| Уход первого экрана: параллакс + затухание видео **в ноль** к нижней кромке | три `scrub` -триггера |
| Заголовки секций всплывают | `ST.create` в `initAnimations()` |
| Появление блоков пачками | `ScrollTrigger.batch` |
| Свечение под финальным заголовком | `@keyframes breathe` |

Затухание видео вынесено **отдельным** триггером (`start: '38% top'`), а не
слито с параллаксом: оно должно закончиться раньше движения, иначе видео
обрывается по нижней кромке и переход ко второй секции читается как рывок.
Это была прямая правка от владельца — не сливать обратно в один триггер.

Раскрытие плитки при наведении идёт **через `setTimeout` на 70 мс**. Без
задержки быстрый проход мышью по сетке перекладывает `grid-template` несколько
раз подряд, и это ощущается как дёрганье.

### Правило, которое нельзя ломать

Стартовые состояния (`opacity: 0` и сдвиги) висят на `html.js`, а класс `js`
ставится **инлайновым скриптом в `<head>`**, до первой отрисовки — иначе контент
успевает мигнуть.

Класс `html.reveal` — аварийный выключатель, он возвращает всё в видимое
состояние. Его ставят три ситуации: GSAP не загрузился, нет ScrollTrigger,
включён `prefers-reduced-motion`. Плюс таймер на 7 секунд в `<head>`: если к
этому моменту на `<html>` нет `data-booted="1"`, значит `site.js` не выполнился,
и страница раскрывается принудительно. **Любое новое стартовое состояние в CSS
обязано иметь парную строку в блоке `html.reveal`** — иначе при отвале скрипта
кусок страницы останется невидимым навсегда.

## Правка CSS — обязательная проверка

**После любой правки `<style>` считать баланс фигурных скобок.** Незакрытое
правило браузер не подсвечивает: он молча проглатывает всё, что идёт после,
и секции разваливаются далеко от места ошибки. Так уже ломались About и Tools —
остался открытым `@media`, и гигантский логотип After Effects вылез на весь
экран, потому что `.tool-mark svg { width }` до браузера не доехал.

```bash
python -c "import io; s=io.open('index.html',encoding='utf-8').read(); c=s[s.index('<style>'):s.index('</style>')]; print(c.count('{'), c.count('}'))"
```

Причина той поломки — **вырезание блока по `s.index()`**. Селектор `.signature`
встречался дважды: в основном правиле и внутри `@media`, срез поймал первое
вхождение и снёс кусок с закрывающей скобкой. Если режешь диапазон по индексам —
проверяй, что маркер в файле один (`s.count(...) == 1`).

## Медиа — обязательный конвейер

Исходники лежат в `C:\Users\Shambooo\Videos\Portfolio` и `...\Videos\portfolio_2`,
в репозиторий **не кладутся** (4K, 15–40 МБ штука). В `media/` попадают только
пережатые версии:

| Файл | Что это | Параметры |
|---|---|---|
| `<slug>-preview.mp4` | видео в сетке | 960w, без звука, `-crf 28`, `+faststart` (~0,3–0,9 МБ) |
| `<slug>.mp4` | видео в лайтбоксе | 1920w, звук aac 128k, `-crf 22`, `+faststart` (~3–10 МБ) |
| `<slug>.jpg` | постер карточки | осмысленный кадр, 960w, `-q:v 5` |
| `reel.mp4` | шоурил первого экрана | 1600×900, без звука, `-crf 29`, ~2,5 МБ |

```bash
ffmpeg -i src.mp4 -an -vf "scale=960:-2" -c:v libx264 -crf 28 -preset slow \
  -profile:v main -pix_fmt yuv420p -movflags +faststart media/<slug>-preview.mp4
ffmpeg -i src.mp4 -map 0:v -map "0:a?" -vf scale=1920:-2 -c:v libx264 -crf 22 \
  -preset medium -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart media/<slug>.mp4
ffmpeg -ss <кадр> -i src.mp4 -frames:v 1 -vf scale=960:-2 -q:v 5 media/<slug>.jpg
```

**`media/reel.mp4` — шоурил владельца**, собран им в After Effects
(`Desktop\showreel.aep`, мастер `showreel.mov` — QuickTime RLE, 1920×1080,
24 fps, 16,5 с, 1,35 ГБ). В репозиторий кладётся пережатая версия:
`scale=1600:900:flags=lanczos`, `-crf 29`, без звука — 2,49 МБ.

crf 29 выбран сравнением кадров против crf 26 (3,77 МБ): на первом экране
видео идёт с `brightness(.62)` и зерном поверх, разницы не видно, а вес
меньше в полтора раза. Заменить шоурил = перезаписать `reel.mp4` и `reel.jpg`,
в коде ничего не меняется.

**Правила загрузки:**
- У каждого `<video>` в сетке обязателен `poster` — иначе до буферизации карточка чёрная
- `preload="metadata"` в разметке, `IntersectionObserver` поднимает до `auto` и запускает
- Играют **только видимые** превью: девять одновременных декодов роняют fps и батарею
- Полноразмерное видео грузится только по клику; при закрытии лайтбокса `src` снимается
